Lightweight HART: activity recognition on the edge.

A transformer that reads 1.28 seconds of wrist motion, names the activity, and maps it to WHO intensity levels. I tuned it from 84.6% to 88.5% weighted F1, then compressed it with knowledge distillation, targeting an NVIDIA Jetson Orin Nano.

01.

Step counts miss intensity

Most wearables count steps. A slow stroll and a brisk walk can produce the same count but have very different health value. The WHO guideline is written in intensity terms: 150 minutes of moderate or 75 minutes of vigorous activity per week. I wanted a model that recognises the activity itself, runs on the device so raw motion data stays private, and reports minutes in the units the guideline uses.

02.

From raw sensor logs to an edge model

1 Preprocess

Split recordings at gaps over 25 ms, cut 128-sample windows with 50% overlap, normalise each subject with stats from the other eight.

DATA_PAMAP2.py

2 Train

AdamW, warmup + cosine LR, EMA weights, stochastic depth, label smoothing, online Gaussian jitter.

main.py

3 Compress

Five cycles of narrower dense students, each distilled from the previous model.

prune_distill.py

4 Track

Accuracy, F1, size, FLOPs and parameters logged per run to a CSV with comparison plots.

prune_tracking.py

5 Deploy

Float32 and INT8 TFLite export, plus mean and P95 latency checks against the 640 ms budget.

benchmark_jetson.py
03.

Separate attention for each sensor

HART (Ek et al., 2023) gives the accelerometer and gyroscope their own attention heads, then mixes them with a lightweight depthwise-convolution branch and a global attention pass. I added a multi-scale convolutional tokenizer, which produced the largest single accuracy gain.

04.

84.6% to 88.5% weighted F1

Every run was scored on the same held-out test fold (20% per subject, never used for model selection). The biggest gains came from the multi-scale tokenizer, a lower peak learning rate (5e-4) and a slower EMA decay (0.9999).

05.

Smaller dense models, not sparse ones

Unstructured pruning leaves irregular sparsity that edge hardware can't exploit. Instead, each cycle builds a narrower dense HART and trains it against the previous model's softened outputs. The best cycle is chosen on validation accuracy only.

∑ Distillation loss

L = CE(y, s) + 0.5 · T² · KL(tT ‖ sT)

Temperature T = 2.0. Each student becomes the next cycle's teacher.

192 → 176 → 160 → 128 → 112 → 96

◎ Outcome

Cycle 1 (dim 176) reached 88.44% validation accuracy, above its 87.30% teacher, at 15% less storage.

Deeper cycles lost 2 to 8 validation points with only 10 epochs each. Longer schedules per cycle are the next experiment.

06.

Activities become WHO minutes

Each prediction is mapped to a MET value and a WHO tier. Windows advance every 0.64 s, so the system can total moderate-equivalent minutes (vigorous counts double) against the 150-minute weekly target.

07.

Making the results trustworthy

  • Fixed test-set leakage. The original compression script picked its best cycle using test accuracy. I moved selection to a validation split so the reported test numbers stay unbiased.
  • Fixed 21 bugs across five files, including DropPath never being applied, a swapped confusion-matrix axis, a 10-vs-18 class-count mismatch, and NaN values slipping through metric logging.
  • Stopped leakage between subjects by normalising each subject with statistics from the other eight.
  • Made runs reproducible with JSON configs, fixed seeds, and a metadata file per run that records hyperparameters, library versions and dataset checksums.
08.

Open problems

int8 Quantisation

Post-training INT8 drops to about 46% accuracy, so calibration is failing. Next: a class-balanced representative set, or quantisation-aware training.

>_ On-device numbers

The Jetson benchmark script is written but hasn't been run on hardware yet. TensorRT FP16 export comes after that.

⌬ Unseen users

The test fold comes from the same nine subjects. Leave-one-subject-out evaluation will measure true cross-user generalisation.

± Variance

A 1.5-point spread between identical configs means comparisons need multiple seeds and mean ± std reporting.
